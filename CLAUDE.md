- Always use the `coder` agent (Agent tool, subagent_type "coder") to edit code. Reading, searching and explaining code can be done directly; once a change is decided, hand it to `coder` with the file, the change, the reason, and how to verify it.
- When the user requests a new feature (not a small, well-defined fix/edit), use the `developer` agent (Agent tool, subagent_type "developer") instead of going straight to `coder`. The `developer` agent runs the full plan -> implement -> review workflow (planner, then coder/coder-lead, then reviewer) and uses `coder` internally, so this doesn't conflict with the rule above. For small, well-defined edits, hand off to `coder` directly as usual. This routing rule applies only when you (Claude) are responding directly to the user in the top-level conversation — not when you are running as a subagent (e.g. as `developer`, `coder-lead`, `coder`, `planner`, `reviewer`, or any other dispatched agent). A subagent must never apply this rule to itself or spawn another `developer`/`coder` based on it; it should just follow its own agent definition.
